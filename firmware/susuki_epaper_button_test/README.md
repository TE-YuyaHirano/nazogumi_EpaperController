# SUSUKI e-paper button test

M5Stack Basic v2.7のA/B/Cボタンで、Waveshare RPi Zero PhotoPainterに閉じ目と開き目の絵を表示するテストです。

## ボタン

- A：閉じ目を表示
- B：現在の絵から切り替え
- C：開き目を表示

電子ペーパーの更新中はボタン操作を受け付けません。更新には十数秒から数十秒かかります。
すでに表示中の状態と同じボタンを押した場合は再更新しないため、不要な全画面点滅は発生しません。

## 更新時の点滅について

この6色電子ペーパーは、色を正しく定着させて残像を消すため、全画面更新中に数回点滅します。これはパネルの正常な更新動作です。このモデル向けの部分更新は提供されていないため、点滅そのものを安全に無効化することはできません。

本プログラムでは、表示が実際に変わるときだけ更新します。本番運用でも、時刻判定のループごとではなく「閉じ目から開き目」「開き目から閉じ目」へ状態が変わった瞬間だけ `showPicture()` を呼んでください。

## 配線

| PhotoPainter信号 | Raspberry Pi物理ピン | M5Stack側面ラベル | GPIO |
|---|---:|---:|---:|
| DIN / MOSI | 19 | G2 | 2 |
| CLK / SCLK | 23 | G5 | 5 |
| CS / CE0 | 24 | R2 | 16 |
| DC | 22 | T2 | 17 |
| RST | 11 | 下辺のSCL（SDAとMOの間） | 22 |
| BUSY | 18 | AD | 35 |
| PWR | 13 | DA（2個目） | 26 |
| GND | 6など | GND | GND |

RTCはこのボタンテストでは接続しません。RSTには下辺のSCL端子（GPIO 22）を使い、内蔵スピーカーと共用のGPIO 25は使用しません。下辺のSCLはGROVE AのSCLと電気的に同じ端子ですが、ピンソケット側から接続できます。既存のGND配線はそのままです。R0/T0を使わないため、USBシリアルやファームウェア書き込みとも競合しません。SCLをRSTに使う間は、GROVE Aを含むI2C機器は同時使用できません。

## 電源

初回テストではPhotoPainterとM5Stackを、それぞれ別のUSB-Cから給電してください。両者はGNDだけ共通にし、5Vと3.3Vは接続しません。

## Arduino IDE

1. ESP32ボード定義をインストールします。
2. Library Managerから `M5Unified` ライブラリをインストールします。
3. `susuki_epaper_button_test.ino` を開きます。
4. ボードは `M5Stack-Core-ESP32` を選択します。
5. 書き込み後、M5Stackの画面に `READY` が表示されたらAまたはCを押します。

M5Basicの画面は20秒間操作しないと自動で消灯します。消灯中はA/B/Cのいずれかを押すと再点灯し、その最初の操作では画像切り替えやメニュー遷移を行いません。

## 切り分け

- M5Stackに `EPD ERROR / BUSY` と出る：BUSY、PWR、RST、GNDを確認します。
- 何も変わらない：DIN、CLK、CS、DCを確認します。
- 画像の上下が逆：実画像を組み込む段階で180度回転して変換します。
- 更新中に長時間止まる：USB電源容量とPhotoPainter本体の電源スイッチを確認します。

2枚の写真は6色・縦向きへ変換してプログラム内に格納しているため、SDカードは不要です。変換前画像と6色プレビューは `assets` フォルダ、再変換ツールは `tools/convert_epaper_images.py` にあります。

M5Stack内蔵液晶とのSPI競合を避けるため、電子ペーパー通信にはソフトウェアSPIを使用します。
画像送信部分はESP32のGPIOを直接操作して高速化しています。ただし、パネル自身の全画面リフレッシュ時間と点滅回数は画像の色数によらず固定に近いため、写真をモノクロ化しても更新時間はほぼ短くなりません。
